심사자가 ‘무엇을 읽었는가 → 어떻게 게시하는가 → 결과와 운영 규칙은 지켜지는가’를 차례로 확인하도록 구성했습니다. 16:9, 1920×1080을 기본 제작안으로 두며 OBS에서 실제 지원·해상도를 확인합니다. 모든 화면은 고정된 정면 앱 캡처입니다. 화면이 전환되어도 같은 영상·초안·계정을 유지하고, 계정 전환 장면에서만 변경을 분명히 보여줍니다.

촬영에 사용할 코드 화면

React → Express → Vertex AI 또는 Playwright → SQLite → SSE → React

  1. Express 게시 전 검증 validateComment(input.comment, draft.evidence, draft.context)로 본문과 근거를 검사한 뒤 게시 예약으로 넘어갑니다.
  2. SQLite 게시 예약 store.reserve(video, draft, input.comment, input.profileId)가 트랜잭션에서 중복과 일일 한도를 확인합니다. 고유 인덱스가 같은 영상에 대한 두 번째 예약을 막습니다.
  3. Playwright 입력과 결과 확인 editor.pressSequentially(job.comment, { delay: 70 })로 입력합니다. 게시 뒤 findOwnComment(page, job, profile)로 작성 채널과 본문을 확인합니다.

Node.js 24에서 서버와 브라우저 제어를 함께 실행합니다. SQLite에 기록된 진행 상태는 SSE로 React 화면에 전달합니다.

TTS·자막 제작 조건

  • 요청 모델: gemini-3.8-flash-tts. Google Cloud 공식 문서의 aiplatform.googleapis.com·global GenerateContent 경로를 확인했습니다. 현재 프로젝트의 합성 요청 권한은 단계 5에서 확인합니다.
  • Gemini Developer API, AI Studio API 키 또는 다른 과금 경로로 자동 전환하지 않습니다. Vertex 경로 역시 프로젝트의 과금 정책을 따르며 무료라고 가정하지 않습니다.
  • 한국어 여성 화자, 차분하고 명료한 설명, 과한 방송 톤 없이 듣기 편한 전달을 목표로 합니다. 문서에 나오는 Kore 등을 후보로 두되, 실제 화자 음색은 촬영본 검수 후 짧은 샘플을 듣고 확정합니다. 아직 음성 생성 요청을 하지 않았습니다.
  • 자막은 하단 중앙, 흰 글자와 검은 외곽/반투명 배경, 1~2줄로 배치하고 댓글 입력 영역·게시 버튼을 가리지 않습니다. 문장별 음성 길이로 타이밍을 맞추고 컷편집 후 다시 확인합니다.
  • 인증 JSON, 환경 설정, 쿠키, 로그인 입력, Google 계정 정보는 촬영 장면에 포함하지 않습니다. OBS는 필요한 전용 창만 캡처하고 마이크·시스템 알림을 점검합니다.

기술 근거: Google Cloud 모델 문서 · 공식 GenerateContent 예제. 문서상의 모델 지원과 이 계정의 실제 호출 권한은 구분합니다.
