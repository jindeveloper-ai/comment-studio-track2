최종 편집 목표 2분 50초. 실제 AI/네트워크 대기는 촬영 원본에 남기고 사용자 재검수 후 컷편집합니다. 촬영·TTS 생성 전 검수 대기 상태입니다.

- 화면: 대시보드 전체에서 영상 불러오기를 눌러 썸네일·제목·채널·게시 날짜를 보여줍니다.

## S02 · 00:15–00:45 · 영상 선택·근거·초안

- 길이: 30초
- 화면: 일반 최신 목록에서 미게시 영상을 고릅니다. 고민 한 줄, 수집한 근거, 댓글 초안과 게시 전 검증 결과를 보여줍니다.
- 프레임: 고정 정면 앱 캡처. 원본 연속 촬영, 승인 후 필요한 하드 컷.

영상을 고르면 익스프레스가 요청을 받아 버텍스 에이아이에 수집 자료를 전달합니다. 실제 근거를 함께 보여주어 게시 전에 사람이 초안을 확인할 수 있게 했습니다. 타입스크립트로 데이터 형식을 공유하고, 조드로 실제 요청 값을 검사합니다.

## S03 · 00:45–01:50 · 실제 YouTube 타이핑·게시·확인

- 길이: 65초
- 화면: 유튜브1 선택 → 댓글 달기 → 전용 Chrome의 한국어 YouTube → 빈 댓글 창 → 글자별 입력 → 게시 클릭 → 작성 채널과 댓글 본문 → 대시보드 게시 완료·댓글 보기. 댓글 영역이 보이도록 전환하고 작성 채널과 본문을 잠시 고정해 보여줍니다. 입력부터 확인까지 원속도 한 테이크로 유지합니다.
- 프레임: 고정 정면 앱 캡처. 원본 연속 촬영, 승인 후 필요한 하드 컷.
- 음성: 촬영본 검수 후 아래 TTS 삽입.

플레이라이트로 전용 크롬 프로필을 열어 한국어 유튜브 화면에서 실제 댓글 창을 조작합니다. 한 글자씩 입력하고 게시합니다. 작성 채널과 본문이 일치하는 댓글을 찾으면 게시 완료로 기록합니다.

## S04 · 01:50–02:10 · 서버에서 강제하는 운영 규칙

- 길이: 20초
- 화면: 같은 영상에서 다른 프로필을 고르고 재게시 차단 안내를 보여줍니다. 일일 게시 횟수와 운영 기록을 함께 보여줍니다.
- 프레임: 고정 정면 앱 캡처. 원본 연속 촬영, 승인 후 필요한 하드 컷.
- 음성: 촬영본 검수 후 아래 TTS 삽입.

스큐라이트 트랜잭션에서 게시를 예약하고 고유 인덱스로 중복을 막습니다. 계정을 바꿔도 영상당 한 번만 게시할 수 있고, 한국시간 기준 일일 한도와 이력은 재시작해도 유지됩니다.

## S05 · 02:10–02:50 · 구현 흐름과 제작 의도

- 길이: 40초
- 화면: React → Express → Vertex AI 또는 Playwright → SQLite → SSE → React 순서로 표시합니다. 코드 화면은 게시 전 검증, 게시 예약, 글자별 입력과 댓글 확인만 짧게 보여줍니다. 프로필 순환·링크 입력·유망 영상 초안 전용 표시로 마무리합니다.
- 프레임: 고정 정면 앱 캡처. 원본 연속 촬영, 승인 후 필요한 하드 컷.
- 음성: 촬영본 검수 후 아래 TTS 삽입.

노드 제이에스 이십사에서 로컬 서버와 브라우저 자동화를 함께 실행합니다. 익스프레스가 요청을 검증하고 버텍스 에이아이는 초안을, 플레이라이트는 게시를 처리합니다. 결과는 스큐라이트에 저장하고, 서버가 에스에스이로 변경 상태를 보내면 리액트 화면이 바로 갱신됩니다. 실제 영상 근거와 게시 결과를 한 화면에서 확인하도록 만든 이유입니다.

TTS는 Google Cloud 공식 모델 문서의 global aiplatform.googleapis.com 경로만 사용하며 합성 호출은 촬영본 검수 뒤에 진행합니다. 실제 화자·재생 시간·음량·자막 품질은 아직 검증 전입니다.
